## 目录结构：先按朝代，再按书（或体裁）

数据集不再平铺在根目录，而是按朝代分层；朝代下面是「一部书一个目录」（总集、别集、选本），
或者按体裁分「诗 / 词 / 文」。选本不往总集里塞，总集也不因为收的篇目跨代就往上提一层。

```
先秦汉魏晋南北朝/
  诗经/  楚辞/  曹操诗集/
  古诗源/汉魏六朝诗.json        沈德潜《古诗源》里先秦以外、隋以前仍未见于他书的 12 首
  诗文总集/
    乐府诗集/                 郭茂倩《乐府诗集》选篇，按卷分文件
    昭明文选/                 《文选》445 篇，按体类分 90 个文件
唐代/
  诗/全唐诗/                  《全唐诗》+《全宋诗》：poet.tang.*、poet.song.*
唐五代/
  词/五代诗词/                花间集、南唐二主词
宋代/
  词/宋词/                    《全宋词》ci.song.*
元代/  元曲/yuanqu.json        《全元散曲》
明代/  诗/古诗源·明诗.json      《古诗源》里的明诗切片
清代/  诗/古诗源·清诗.json      《古诗源》里的清诗切片
```

几条约定：

- **朝代目录写全称**，跨代的综合体（乐府、文选、古诗源）归它取材的主要时段：
  《乐府诗集》与《昭明文选》都在 `先秦汉魏晋南北朝/诗文总集/`，因为两书所收以此为大宗；
  它们各自收到的唐诗、唐五代词，凡在 `唐代/诗/全唐诗/` 已有同一首正文的，按「一件作品只留一份正文」删去（见 [`docs/`](docs/)）。
- **《全宋诗》仍在 `唐代/诗/全唐诗/poet.song.*`**，不另开目录：它是《全唐诗》之后追加的一批文件，
  历史上就在那里，拆开会让已有的对勘记录（`fix_progress.json`、`docs/*.tsv`）全部对不上。
  这是唯一一个目录名与内容不符的位置，已在 `loader/datas.json` 里按 dataset 名「全唐诗全宋诗」标明。
- **一件作品只留一份正文**。《古诗源》与《诗经》《楚辞》《全唐诗》《全宋诗》《全宋词》逐字相重的，删掉《古诗源》
  那一份，诗仍可在《古诗源》里查到——按选本查的入口是 `anthologies/` 的目次与记录上的 `tags`，不靠目录里留副本。
  原先从《古诗源》里摘句的 7 首《诗经》与《橘颂》，现在只保留《诗经》《楚辞》的全文版本。
- **选本切片随作者朝代走**：《古诗源》里唐代以前的留在 `先秦汉魏晋南北朝/古诗源/`；宋、明、清的切片放在
  对应朝代目录，文件名一律 `古诗源·宋诗` 这种「书名·卷名」，一眼看得出出自哪部选本、归在哪个朝代。
- **加载入口是 `loader/datas.json`**：路径变了，dataset 的 key 不变，用 `PlainDataLoader` 的下游不必改代码。
  `宋代/词/宋词/` 是一个 dataset（`songci`），明诗、清诗各一个（`gushi-yuan-ming`、`gushi-yuan-qing`）。
- 目录与文件的移动只改路径，不动正文；`fix_progress.json` 的键同步改成新路径。

## 本 Fork 的数据修正

本仓库 fork 自 [chinese-poetry/chinese-poetry](https://github.com/chinese-poetry/chinese-poetry)。原数据爬取自网络，存在大量乱码、缺字与重复。本 fork 以古籍检索为证据做了系统性修正，并去掉了唐诗部分的重复数据（见下文「对使用者的影响」）；JSON 字段格式不变，只在部分唐诗记录上新增了 `prologue`。`fix_progress.json` 只记录哪些文件查过、何时、由谁、结论如何，不保留逐条勘误日志——每一处改动看 git 历史即可，全库随时可用 `scripts/check_structure.py` 重查。

### 主要修改

| 类别 | 说明与示例 |
| --- | --- |
| 形近 / 音近错字 | 全唐诗 与 御定全唐詩（同一部《全唐诗》的另一份录文）逐句对勘，一字之差处以识典古籍判定：只改「无任何古籍支持」的一方，两读皆有依据的视为异文保留。如 `人間寒署` → 寒暑、`鶴淚眇雲端` → 鶴唳、`朝庭` → 朝廷 |
| 选本互校错字 | 花间集、南唐二主词、唐诗三百首、千家诗、水墨唐诗 与 全唐诗 / 宋词 中的同一作品逐句互校，一字之差以识典古籍判定，两边的错字都改（另同步 11 个「词牌·首句」标题）。如水墨唐诗 `云开远见洛阳城` → 汉阳城、花间集 `近拂提` → 近拂堤、全唐诗 `腰下實玦` → 寶玦。帷/幃、消/銷、怎奈/争奈 等用字差异不改 |
| 繁简转换错误 | 简转繁「一对多」选错字，逐处核对上下文：`鬥酒`/`鬥牛` → 斗、`空穀`/`陵穀` → 谷、`後土`/`後稷` → 后、`白發`/`束發` → 髮、`範蠡` → 范、`書劄` → 書札、`徵君` 误作 征 等 |
| `□` 缺字补全 | 只补至少 2 种独立古籍一致的；原书同样缺字的保持 `□`。如辛弃疾「峡束□江」→「峡束苍江」、周邦彦「□□唤酒」→「名娃唤酒」 |
| 日文假名 / 注音符号乱码 | 如 `け然` → 翛然、`荼コ` → 荼䕷、`ゐ惶` → 恓惶、`蹴リ` → 蹴踘、`银筝不会ㄐ` → 搊 |
| 私用区（PUA）字符 | 显示为空白或方块的私用区字符，如「圈＋PUA」→ 圈䙡（禅宗语）、「泬＋PUA」→ 泬㵳（天空）、杜牧「分明㩳㩳羽林槍」 |
| 西里尔 / 希腊字母乱码 | 如 `风月正и娟` → 婵娟、`七Α开颜` → 七秩、`阁门珠路Λ` → 𦌊 |
| GBK 字节错位 / 制表符乱码 | 如 `忒�山苛樱�` → 忒煞娇劣、`┾却` → 拚却 |
| 诗句、词句漏字 / 衍字 | 依常体句长检出、经古籍核对。如李白「起来向壁不停手」后缺「一行數字大如斗」、苏轼「乃使驥騄隨蹇步」、范成大「忘却天涯漂泊地」、和凝「时时微雨洗~~劫~~风光」 |
| 作者名 | `赵必□` / `赵必��` → 赵必𤩪（四库本《覆瓿集》署名） |

逐类的修了多少条没有单独累计：勘误日志不保留，改动以 commit 为准。

另有 68 处看似字数不齐、或与通行本不同的诗句，经古籍核实为原貌（又一体、早期版本异文），**未作修改**。例如白居易《琵琶引》「枫叶荻花秋**索索**」是《全唐诗》与宋代文献的原文，通行的「秋瑟瑟」出自明清选本。

### 修正原则

- **以古籍为证，不凭印象**：主要依据[识典古籍](https://www.shidianguji.com)中的古籍刻本、抄本的文字，辅以搜韵、古文岛、汉典；找不到可靠依据的标记为 `needs_review`，不作猜测。
- **不以通行本改底本**：课本或选本的写法不等于原文。
- **保留原字形**：只改动出错的字，并沿用本库已有的写法（如 搊 而非类推简化的 𫼝）。

### 对使用者的影响

- **删除 `御定全唐詩/`**：它与 `唐代/诗/全唐诗/` 中的唐诗是同一部《全唐诗》的两份录文，对勘完成后不再保留（上游仓库仍有）。上表中 全唐诗 一侧的修正都保留在 `唐代/诗/全唐诗/` 里。
- **唐诗选本并入全唐诗，去掉重复**（逐首记录见 [`docs/唐诗去重.tsv`](docs/唐诗去重.tsv)）：
  - 删除 `全唐诗/唐诗三百首.json`：它是从 `poet.tang.*` 抽出的副本，且有 3 首署名有误（如金昌绪《春怨》记作宋僧释明辩）。366 首都已在 `poet.tang.*` 中找到，标签并入原记录，按 `tags` 中的「唐诗三百首」筛选即可。
  - `水墨唐诗/` 中能在全唐诗找到的 172 首，在 `poet.tang.*` 原记录上加标签「水墨唐诗」并带上赏析 `prologue`。文件只留下全唐诗未收或改写较多的 4 首（如杜牧《清明》）。
  - `poet.tang.*` 删除 548 首同时收在 `唐五代/词/五代诗词/huajianji/`（花间集）或 `唐五代/词/五代诗词/nantang/`（南唐二主词）中的同一作者的同一首词，以带词牌结构的选本为准。作者不同的属于归属异说，两边都保留，如《应天长》李璟／李煜。
- **补入 poem-wechat 语料中本库确实没有的 65 首**：上一轮判重是拿（标题, 作者）回查上游条目再比正文，同名作品会串（`文选` 卷上四个《杂诗》全被取成了沈佺期那首）；这一轮改成**按上游 id 精确取正文**，对上游判为「没有」的 76 条逐条重判，剔掉上游自身的重复条目与已在 `纳兰性德/` 的 3 首，收 65 条，逐条记录见 [`docs/wechat_corpus_collect.tsv`](docs/wechat_corpus_collect.tsv)：
  - `近现代诗/`（41 首）：课本里的近现代诗（毛泽东、鲁迅、艾青、余光中等）以及几篇文言课文（《三峡》《核舟记》《劝学》《老子四章》），本库原来没有这一块。
  - `近现代诗/元明清詩.json`（8 首）：课本选目的元明清绝句（袁枚、秋瑾、戚继光、文徵明等），进不了《古诗源》（那部书到隋为止，现按朝代分置于 `先秦汉魏晋南北朝/古诗源/`、`明代/`、`清代/`），仍归入这本横跨朝代的诗选。

  - `宋词三百首/`（4 首）：清词（纳兰性德、夏完淳）与个别宋人僻调（查荃《透碧宵》），本库此前一首都没有；其余多为已有作品的异文，按「题同文异两存」不收。

  - 课内、近现代、古诗非唐、节日节气这几部是横跨朝代体裁的课本选目，不是一部书，按体裁并入上面的目录，没有各自开目录。
- **整批先按正文去一次重，再分文件**：课内/近现代、古诗非唐/课本之间有重出篇目（《卜算子·咏梅》《七律·长征》《沁园春·长沙》《沁园春·雪》《墨梅》《潼关》），不分先后会落成两份正文；这 6 首各只留一条。

- 底本原有的 `□` 缺字、以及古籍中也无法确认的乱码仍然留在数据里：`python3 scripts/check_structure.py` 会随时列出这些位置（`□` 缺字约 4500 处、裸露的私用区字符 300 余处，多为底本残缺的罕见字），不逐条转录进进度文件。`唐代/诗/全唐诗/error/` 是上游标出的问题数据，不在发布范围内，标记为 `out_of_scope`。

导入规则（脚本见 [`scripts/wechat_corpus/`](scripts/wechat_corpus/)）：

- **繁体、每行一句**，字段与原库一致（`author` / `paragraphs` / `title`，从别处并进来的题名另记 `sources`）。上游简体正文用 OpenCC `s2twp` 转换，只转换字形，不改字。
- **一件作品只留一份正文。** 去重不按标题按正文：繁体转简、去标点后逐字比较，不足 8 字的不判（短句重名太多）。标题靠不住——上游「感遇·其一」其实是全唐诗「感遇十二首 **四**」，按题名对会漏掉 48 条。
  - 与**库中原有**条目重复的，新条目不收，把它的题名挂到原条目的 `sources` 上：「这首也见于《乐府诗集》卷三」这层信息留住，正文仍只有一份。
  - 新目录**内部**重复的（《垓下歌》乐府诗集、古诗源各收一次；古文观止把《心術》排了两遍），同一部里后出现的那条删掉；跨部重复的两条都删，题名挂回原条目。
  - 这样剔掉 110 条，逐条记在 [`docs/wechat_corpus_dedupe.tsv`](docs/wechat_corpus_dedupe.tsv)。
- **默认不并入 `唐代/诗/全唐诗/`、`宋代/词/宋词/`**：本库的唐诗去重、选本互校都建立在那批文件之上（见上文「对使用者的影响」），选本另立目录可以保住这些口径，也不必重跑一遍去重。元曲三百首是例外，已按 `scripts/merge_yuanqu.py` 并回 `元代/元曲/yuanqu.json`，见下条。
- 上游的译文、出处、学段、难度、节选等展示字段**不入库**——本库只有正文。

## 与 GitHub 的同步

本仓库是 [belem/chinese-poetry](https://github.com/belem/chinese-poetry) 的镜像：内容与上游 **逐字节一致**，只额外多出 `.cnb.yml` 和 `.cnb/` 两个同步配置。

两端都在 `develop` 分支上直接 commit，不走 PR。

| 方向 | 触发 | 动作 |
| --- | --- | --- |
| CNB → GitHub | `develop` 推送 | 直接 push 到 GitHub `develop` |
| GitHub → CNB | 每 6 小时 / 手动 | fast-forward 拉取 `develop` |

- `main` 不参与自动同步；上游默认分支是 `fix-typo`，本仓库固定用 `develop`。
- 只做 fast-forward。两侧分别推进导致分叉时任务失败，人工合并，绝不强推。
- 上游的 `.github/workflows` 原样保留，但在 CNB 镜像里不会运行；要跑对勘等定时任务请用 GitHub 侧。

### 凭据

GitHub PAT 存在内部密钥仓库的 `pair.yml` 里（路径见 `.cnb.yml` 顶层的 `SECRETS_SLUG` / `SECRETS_FILE`），由各任务用 `imports` 引用后注入为环境变量。

- 字段名 `GITHUB_TOKEN` 或 `GITHUB_PAT` 都行，`sync.sh` 两者都认。
- PAT 需对 `belem/chinese-poetry` 有 **Contents: Read and write**。
- 密钥仓库禁止本地 clone / 推送，只能 Web 端改；引用放行条件由密钥仓库文件里的 `allow_slugs` 等字段控制（文件引用语法见平台文档）。
- 密钥仓库路径与文件名在 `.cnb.yml` 顶层环境变量 `SECRETS_SLUG` / `SECRETS_REF` / `SECRETS_FILE` 里改一处即可。

未注入时同步会跳过，日志打印 `[sync] 没有 GITHUB_PAT / GITHUB_TOKEN，跳过与 GitHub 的同步` 和排查提示；注入成功只打印凭据长度，绝不打印值。

### 手动触发

任务 `manual-sync`（事件 `api_trigger_sync`）支持手动运行，方向由环境变量 `MODE` 决定：

- `MODE=push`：CNB → GitHub
- `MODE=pull`：GitHub → CNB
- `MODE=both`：先拉后推（默认）

```bash
cnb build start-build --branch develop --event api_trigger_sync --env MODE=push
```

事件名不能写成裸 `api_trigger`：密钥仓库 `pair.yml` 的 `allow_events` 是 `api_trigger_*`，通配符不匹配自身，裸事件会在 Prepare 阶段被拒。

### 合并冲突提示

同一个 commit 若在两边都产生（比如 GitHub 侧的定时脚本改了文件、CNB 侧同时手动编辑），会形成分叉。此时先在本机把两侧 merge 成一个，再推 `develop`。
