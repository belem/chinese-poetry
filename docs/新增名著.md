# 新增四部长篇小说（2026-10）

四大名著此前不在库里。这一批按版本从[识典古籍](https://www.shidianguji.com)整部取，
一部书一个目录，不设「名著/」这一层。

**识典上的书分两种：扫描件 OCR，和已经排好的正文。** 章节页把正文渲染在
`<article class="chapter-reader">` 的 `<p>` 里，HTML 直出——这种跟 OCR 无关。
上一版四本都是渲染后取 `<p>`，取的却可能是扫描件转出来的文字；那本《水浒传》就是这么来的：
回次行糊成「弟三十七回」，正文却是能读的，错与不错搅在一起，看不出哪儿坏了。这次换了三本的底本：

| 书 | 目录 | 底本 | 条数 | 字数 | 正文来源 |

## 三本换了底本，为什么

识典的同一部书往往收了好几个本子，扫描件与排印本混在一起，要一本一本看。

- **《红楼梦》**：程甲本（GY025，上一版的底本）只有扫描件，正文一个字都没直出。
  「林黛玉」印成「林代玉」、「拋父」印成「抛父」，都是 OCR 认错形近字。庚辰本
  （7428573169323081747）是排好的正文，改用它。代价是庚辰本十七、十八回原本未分开，
  全书 79 回而非 120 回；程甲本 120 回本等有干净的排印本再补。
- **《西游记》**：世德堂本 NA11023 的正文是 HTML 直出的，上一版取的也是它，多绕了一圈浏览器。
  这一版直接取 HTML，100 回齐全（上一版有一条回次认错）。
- **《三国演义》**：嘉靖壬午本一页往往连排几则，靠页面小标题（h3）切。上一版 156 条里有一批
  「整卷压在一页、未逐则切开」的记录，这一版按 h3 切准了，120 条；仍有无小标题的页并入上一则。
- **《水浒传》**：容与堂本只有扫描件，另一部「李卓吾先生批评忠义水浒传」（SDZJ0548）只到
  30 回上下，凑不成全本。所以正文仍是 OCR，只把回次与回目换成容与堂本的回目表，
  不再信 OCR 出来的回次行。**这一本还没洗干净**，见下。

## 为什么放在朝代目录下

`docs/目录结构.md` 第一条原则是「目录按一部书切」，第二层才是书。四部书的作者朝代没有争议
（罗贯中、施耐庵、吴承恩是明人，曹雪芹是清人），按作者朝代落位即可；不需要另立「名著」这个
按名气切的维度——否则同一部书迟早会有两份正文。

## 字段

沿用 `docs/目录结构.md` 的记录契约：`title`、`author`、`dynasty`、`paragraphs`、`id`。
没有 `sources`（不写语料出处名，见 AGENTS.md）。

题名格式是「第N回　回目」。《三国演义》的嘉靖本不分回、只分则（一卷若干则），故作「第N则」。

## 底本各自的坑

**《水浒传》还是脏的。** 容与堂本只有扫描件 OCR，按定长（26–30 字）折行、一行一段。处理办法：
- 按句末标点把折行重新合并成段；
- 回次与回目不采信 OCR 的回次行，以容与堂本回目表为准；
- 损字仍在。这本在 `fix_progress.json` 里记 `needs_review`，等干净的排印本整本替换。

**《三国演义》没有逐则切开的部分。** 嘉靖本靠页面小标题切则，没有小标题的页并入上一则，
所以是 120 条而不是通行本的 240 则。

**《红楼梦》是庚辰本（79 回）。** 十七、十八回底本未分回，故一条；回目取自页面 h3 或正文首行的回目行。

**《西游记》的李卓吾总批已剔除**（`總批：` 及其后整段），序与题辞未收。

## 抓取脚本

```bash
cd scripts/shidian && npm install && npx playwright install chromium

# 1. 目录：从书页取起点，顺「下一篇」链串齐章节 id
node build_cat.mjs 7428573169323081747 /tmp/hlm/catalog.json
# 2. 正文：每章渲染后的 <p> 段落（不解析内嵌 paragraphList，那里的句子是碎的）
node text.mjs 7428573169323081747 /tmp/hlm/catalog.json /tmp/hlm/raw.json
# 3. 落成记录
python3 convert.py /tmp/hlm/raw.json 清/小说/红楼梦/hongloumeng.json --book hongloumeng
```

| 书 | bookId | convert 参数 |
| --- | --- | --- |
| 三国演义 | CADAL02111749 | `convert_sanguo.py`（版式不同，单独一支） |
| 水浒传 | NGJ89241199901879587548 | `--book shuihu` |
| 西游记 | NA11023 | `--book xiyou` |
| 红楼梦 | 7428573169323081747 | `--book hongloumeng` |

`build_cat.mjs` 的目录树是虚拟列表，一次只渲染十几项、滚到底也只多几项，所以靠「下一篇」串链；
这也是为什么不能直接用 `chapter.mjs` 的目录正则抓这几本。
