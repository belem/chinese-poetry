# 选本对齐（唐诗三百首 / 宋词三百首）

## 为什么会漂

本库把选本并进了 `唐/诗/全唐诗/`、`宋/宋词/`，靠 `record['tags']` 标注「这首属于某选本」。
目录按朝代分层之后（《全宋诗》已从 `唐/诗/全唐诗/` 拆到 `宋/诗/全宋诗/`），本表 `where` 列给的是相对仓库根的全路径。
tag 是爬取时打上去的，从来没跟底本目次比对过。于是三类问题都看不出来：

- **混入**：挂着 tag，但底本里没有这首
- **漏收**：底本里有，库里没挂 tag
- **重覆**：同一首在库里存了多条

而且旧办法根本查不了——没有目次可比，"是不是这个选本"只能凭印象。

## 解法：先有目次，再谈归属

`anthologies/` 下每部选本一份目次，条目只记机器校验需要的字段：

```json
{
  "no": 2,
  "category": "七言古詩",
  "author": "白居易",
  "title": "長恨歌",
  "first_line": "漢皇重色思傾國御宇多",
  "source": "XYXTSSBSZS/1mhlf2b18tp2a"
}
```

- **`category` 是照妖镜**。唐诗三百首按五古/七古/乐府/五律/七律/五绝/七绝编排，
  一首诗挂错体类一眼就能看出来。这是选本最强的指纹。
- **`first_line` 是匹配锚点**，取首句前 10 字，只用来对，不是正文。
- **不带 `author` 做匹配条件**：选本的署名本身就会错（本库已修过：金昌绪《春怨》
  被记成宋僧释明辩）。作者只用于人工复核时对照。

底本都用识典古籍的扫描本，正文用 `scripts/anthology/crawl_book.mjs` 顺序抓下来：

| 选本 | 底本 | bookId |
| --- | --- | --- |
| 唐诗三百首 | 唐詩三百首注疏，蘅塘退士編、章燮注，上海掃葉山房石印本 | `XYXTSSBSZS` |
| 宋词三百首 | 宋詞三百首，朱祖謀編，民國十三年朱祖母集解本 | `7374122395470135333` |

## 归属不用分类算法

选本是有限的、互不相交的列表，判定归属是 **one-to-one 匹配**，不是分类问题。
作者朝代、风格相似度、"像不像这个选本"——全是噪声源，别用。

`scripts/check_anthology.py` 只做机器能做准的那件事：按首句的规范形检索对应朝代的记录。

两道闸必须留着，否则结论是假的：

1. **年代**：唐诗三百首只认 `poet.tang.*`，宋词三百首只认 `ci.song.*`（选本目录 2026-10 已删，正文都并作 tags）。
   宋人诗里嵌着大量唐诗，不比年代就会把《全宋诗》的记录当成《唐诗三百首》。
2. **规范形要双向**：`t2s` 统一简繁，Unihan 异体表统一 飮/飲。
   但 Unihan 表的代表形取字典序最小，会把 丘 并成 㐀 这种生僻字，
   所以取族里的常用字形（GB2312 内优先）作代表，两个方向才收敛到同一 key。

```bash
pip install opencc-python-reimplemented
python3 scripts/check_anthology.py --out docs/选本对齐.tsv
python3 scripts/check_anthology.py --only tangshi300
```

## 当前结果（2026-10）

| 选本 | 目次条数 | 对不上库 | 未挂 tag |
| --- | --- | --- | --- |
| 唐诗三百首 | 56 | 3 | 53 |
| 宋词三百首 | 284 | 134 | 150 |

`唐诗三百首` 只抽到 56 条：卷一、卷二整卷挤成段落，标题切不准，宁缺毋滥。

`宋词三百首` 的 `对不上库` 从 160 降到 134、`未挂 tag` 从 124 升到 150，是 2026-10-28 那次对勘改的：
`check_anthology.py` 按「首句前 12 字」匹配，底本行款一乱（一句被拆成两行、或第一句不是正文）就整条对不上；
那次改用 6 字片段 + 正文相似度手工对勘，见 [`宋词三百首对勘.md`](宋词三百首对勘.md)。
`未挂 tag` 升高的部分是**对上了但两边正文不同**的条目——`check_anthology.py` 认首句，对上了才叫命中，
这些条目按首句仍算 `untagged`，实际已由人工判定为版本异文，不改。

## 宋词三百首：走向版本证据

逐首对完发现的不是错字，是一处**丢正文**：commit `6fba35e`「宋词三百首并入宋词」时，
把 `ci.song.0.json` 里挂了 `宋词三百首` tag 的记录整条删掉当重复处理，但其中 28 首在现库并无同文副本。
逐条见 [`宋词三百首对勘.md`](宋词三百首对勘.md) 与 [`宋词三百首对勘.tsv`](宋词三百首对勘.tsv)。

### 对齐暴露出来的正文疑点

这些是「目录里有、按首句在库里搜不到」的条目。搜不到不等于库里有错——
底本异文、库里的行内错字，都会让整段首句对不上。逐条核实结果：

| 条目 | 库里现状 | 底本 | 判断 |
| --- | --- | --- | --- |
| 王灣《次北固山下》 | 客路青山**外**，行舟綠水前 | 客路青山**下** | 异文（「下」「外」各本互见），**不改** |
| 杜甫《月夜憶舍弟》 | 戍鼓斷人行，**秋邊**一雁聲 | **邊秋**一雁聲 | 「秋邊」不成词，底本作「邊秋」——**待复核**，可能真是错字 |
| 孟浩然《宿桐廬江寄廣陵舊遊》 | 山暝**聽**猿愁 | 山暝**聽**猿愁 | 库与底本一致，是末三字与通行本「聞猿愁」有别；异文，**不改** |
| 孟浩然《清明日宴梅道士房》 | 林臥愁春盡，**開軒**覽物華 | **搴帷**覽物華 | 标题也是异文（库里作「宴梅道士山房」）；异文，**不改** |
| 王維《酬張少府》 | 晚年**唯**好靜 | 晚年**惟**好靜 | 唯/惟 通用，**不改** |
| 李白《行路難》其二、其三 | 库里合并后的 `其二`、`其三` 首句与底本不同 | — | 底本是连排，切分错位，属目次抽取问题，不是数据问题 |

**没有一条够格直接改。** 这是对的：选本对齐的价值首先是产出一份可核对的差异清单，
不是自动改字。真要改，得逐条回到版本证据上。

### 底本自身的 OCR 讹字

识典古籍这套是本子的扫描 OCR，本身有讹字，抽目次时会带进来。已发现并手工校正的：

| 抓到的 | 应为 | 位置 |
| --- | --- | --- |
| 尋尋**寬**覓冷冷**𩇕**清 | 尋尋**覓**覓冷冷**清**清 | 李清照《聲聲慢》 |
| 乳燕飛華**屠** | 乳燕飛華**屋** | 蘇軾《賀新郎》 |

校正写在 `anthologies/songci300.json` 的 `note` 字段里，可追溯。

**核对原则**：底本 OCR 讹字只影响目次的 `first_line`，不改库里的正文——
库里的正文另有来源，两边要分开判。

## 宋词三百首的篇目：词牌·小题，无小题才用首句（2026-11 修订）

选本里的词大多只写词牌（`浣溪沙`、`贺新郎`、`木兰花`），而同一词牌在库里少则两首、多则七八首，
编目、检索、人工核对都得先看正文才知道是哪一首；更麻烦的是同一首在两批数据里各收一份
（`ci.song.0.json` 简体一批、`ci.song.22000.json` 繁体一批），一个写词牌、一个写原书的小题，
同一首词两副面孔。所以挂 `宋词三百首` tag 的记录，`title` 一律写成 `词牌·` 加一个标识：

```json
{"author": "苏轼", "rhythmic": "念奴娇", "title": "念奴娇·赤壁怀古", "tags": ["宋词三百首"]}
{"author": "晏几道", "rhythmic": "蝶恋花", "title": "蝶恋花·醉别西楼醒不记春梦秋云聚", "tags": ["宋词三百首"]}
```

规则只有几条：

- **底本有小题目就用小题，没有才用正文首句**，小题不再叠首句。2026-11 上一轮一律用首句，
  把「赤壁怀古」「乙卯正月二十日夜记梦」这类底本自带的标识丢了；现在是 `词牌·小题`，
  小题的简繁跟本记录正文走。口径与逐条结果见 [`宋词三百首篇目.md`](宋词三百首篇目.md)
  与 [`宋词三百首勘正.tsv`](宋词三百首勘正.tsv)。
- **只改 `title`**，`rhythmic` 与正文一字不动（唯一例外是 `#1054` 断错行的「老薄幸」）。
- **首句按本记录自己的简繁写法**取正文前 12 字（去标点）：简体那一批写简体，繁体那一批写繁体，
  不把两批数据混成一种字形。底本（识典古籍朱祖谋集解本）只用来核对两批数据是同一首。
- **词牌里的 `・`（U+30FB）换成 `·`**：「凤栖梧・蝶恋花」「青门引・青门饮」这类是同一调的两种写法，
  篇目分隔符统一用 `·`（U+00B7）。
- 两批数据各收一份的同一首，两份写成同一个篇目（上一轮的 `retitle_songci300.py` 用 `DUPLICATES` 对齐；
  这一轮 tsv 里两条各有目次，各自按同一口径写，结果是同一个篇目）。

上一轮做这件事的是 `scripts/anthology/retitle_songci300.py`（一律首句式，已停用），
现在按底本逐条改的是 `scripts/anthology/songci300_titles.py`：

```bash
# 底本用 repo 内的 reference/宋詞三百首，不用联网
python3 scripts/anthology/songci300_titles.py --verbose           # 预演
python3 scripts/anthology/songci300_titles.py --apply --date YYYY-MM-DD --reviewer <名字>
```

写回走 `scripts/anthology/patch_json.py`，只替换 `title` 那一段，不重排文件：
`宋/宋词/ci.song.*` 是历次抓取、拼接留下的，行尾空格、`,` 后留不留空格，一个文件一种习惯，
统一格式会让整份文件都进 diff，改一个字变成改一万行。

## 还没补 tag 的 70 首

`宋词三百首` 的 284 首，有 227 条记录挂了这个 tag（其中 13 首两批数据各收一份、两批都挂了），
它们全部改成了「词牌·小题／首句」。另外 70 首落在**没挂 tag** 的同文副本上 —— 这是
`scripts/check_anthology.py` 的「未挂 tag」一类，与改篇目是两件事，本次没动：没挂 tag 的记录不属于选本，
不该跟着改篇目。要补 tag 时先跑 `python3 scripts/check_anthology.py --only songci300`，按 `docs/选本对齐.tsv` 逐条核。
