# 重复体检

`scripts/check_tree.py` 的输出说明。报告本身在 [`重复体检.tsv`](重复体检.tsv)，可随时重跑：

```bash
python3 scripts/check_tree.py --out docs/重复体检.tsv
```

## 判重口径

**正文前 16 字相同**，比较前简繁归一（`t2s`）、去掉一切非汉字字符。取 16 字而不是整篇，是为了让异文也能对上——半首之后有出入的同一首作品同样是重复。

**只在同一部书内部判重。** 这是这份报告最重要的一条口径。

选本收录总集里的作品，是编书方式，不是重复：《昭明文选》按体类收诗、《乐府诗集》按曲调收诗、《历代》是补录，它们与《全唐诗》《全宋词》大量重叠（实测跨书重 8 处，在 34 万条里可以忽略）。把这些算成重复，报告就会淹没在「《文选》里有《古诗十九首》」这类不是问题的问题里。

同一部书的划法：

| 作用域 | 范围 |
| --- | --- |
| 全唐诗 | `唐/诗/全唐诗/poet.tang.*.json` |
| 全宋诗 | `宋/诗/全宋诗/poet.song.*.json` |
| 全宋词 | `宋/词/宋词/ci.song.*.json` |
| 全元曲 | `元曲/yuanqu.json` 中无 `sources: ["haitang"]` 的部分 |
| 元曲补录 | `元曲/yuanqu.json` 中 haitang 补入的 331 条（同文件不同书） |
| 其他 | 一个顶层目录一部书 |

目录按朝代分层之后，作用域取「朝代/体裁/书名」三级：`唐/诗/全唐诗`、`宋/诗/全宋诗`、`宋/词/宋词` 各成一部书；haitang 的 331 条挂在元曲文件尾部，用 `sources` 分流。

## 三种判定

| 判定 | 含义 | 处理 |
| --- | --- | --- |
| **同作者** | 正文同、作者同 | 同诗重出，可直接删重复的那条。`poet.tang` 里多是「樂府 / 非樂府」两套标题各收一次 |
| **异作者·同题** | 正文同、作者不同、题名同 | 作者归属异说。**两条都留**，改挂 `sources` 互指 |
| **异作者·异题** | 正文同、作者不同、题名不同 | 需人工判：可能是误收，也可能是联句拆条、组诗拆条 |

## 实测结果

正文级重复 3573 条多余记录：

| 书 | 同作者 | 异作者·同题 | 异作者·异题 |
| --- | --- | --- | --- |
| 全唐诗 | 937 | 259 | 539 |
| 全宋诗 | 173 | 489 | 842 |
| 全宋词 | 201 | 80 | 12 |
| 全元曲 | 10 | 8 | 5 |
| 历代 | 8 | 1 | 4 |
| 蒙学 | 1 | 0 | 0 |
| 课外经典 | 2 | 0 | 1 |
| 古文观止 | 0 | 0 | 1 |

几处值得注意的：

- **《全唐诗》的重复是真重复。** `雜曲歌辭 踏歌詞 一` 与 `踏歌詞三首 一` 是同一首，作者都是謝偃，各收一次；`郊廟歌辭 封泰山樂章` 在 `poet.tang.0.json` 与 `poet.tang.4000.json` 各一套。937 条同作者重复绝大多数属于这类，是编书时按「樂府 / 非樂府」两套目录各排一遍造成的。
- **《全宋诗》的重复一半是联句与组诗拆条。** 如《來燕堂聯句》一条记在赵概名下，另一条完整收在欧阳修名下，另有两条同题各记韩绛、王珪——同一首联句被拆成四条。这类不能简单删，得并作一条多人联句。
- **《全宋词》的 201 条同作者重复**，多是 `ci.song.0.json` 与 `ci.song.22000.json` 两批数据重叠（后者是后补的一批），同词牌同正文，一条带 `title` 一条不带。
- **蒙学的 `sanzijing-new.json` 与 `sanzijing-traditional.json`** 是同一部《三字经》的简繁两版，正文归一后相同。这是有意的简繁各一份，不算重复，报告里留着提醒而已。
- **元曲那 10 条同作者重复**，是 haitang 补录的《元曲三百首》曲文与原有 `yuanqu.json` 重了。补录时按「同作者 + 题名覆盖率」判重，这两条题名格式不同（`正宫・白鹤子（四首）` vs `正宫·白鹤子`）没对上。

## 朝代字段体检

`dynasty` 取值不在 `dynasties/dynasties.json` 的 `name` 里的，11288 条：

| 文件 | 值 | 条数 |
| --- | --- | --- |
| `元曲/yuanqu.json` | `yuan` | 11272 |
| `历代/other.0.json` | `yuan` | 16 |

全是拼音，其余地方用中文「元」。与作者索引冲突 0 条——`dynasty` 只在这两处出现，其余目录根本没有这个字段，那才是「朝代对不上」的根因：不是值错了，是没有这一维。

`authors/authors.json` 覆盖 2402 位作者，`poet.song.*` 25 万条里只有 5.1 万条能对上。补 `dynasty` 字段要跟作者索引扩容一起做，是第 4 批的事。
