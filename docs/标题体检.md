# 标题格式体检

`scripts/check_title.py` 的说明。只查 `title` / `chapter` / `rhythmic` / `author` 四个字段，只报告，不修改任何数据。

作者名与题名同一口径 —— 题头就是「作者《题名》」，两者都只留一个半角空格（issue #258）。
查的范围除数据目录外还包括 `rank/`（排行榜数据，题名、作者名与诗作同一份）与
`宋/诗/全宋诗/error/`（不在 `loader` 里，但同一份错字同样该改）—— `check_structure.py`
的 `iter_files()` 把这两处都跳过了，2026-11 之前这批空格一直没被任何检查覆盖。

```bash
python3 scripts/check_title.py                                    # 全库汇总 + 每类前 5 条样例
python3 scripts/check_title.py --only fw_space --show 50          # 只看某一类
python3 scripts/check_title.py --out /tmp/titles.jsonl            # 逐条明细
python3 scripts/check_title.py --baseline scripts/title_baseline.json                       # 与基线比
python3 scripts/check_title.py --baseline scripts/title_baseline.json --files-from-diff origin/develop
```

`--files-from-diff REF` 与 `scripts/check_structure.py` 同口径：只查本次改动的数据文件，
且只比较这些文件涉及到的检查项，别人的问题不算到本 PR 头上。

## 检查项

| 检查项 | 判据 |
| --- | --- |
| `fw_space` | 全角空格 U+3000、不换行空格 U+00A0、U+2000–200A、U+202F、U+205F、制表符 |
| `lead_trail` | 标题与作者名首尾的空格 |
| `multi_space` | 连着两个以上的半角空格 |
| `cyrillic_greek` | 西里尔 / 希腊字母乱码 |
| `kana_bopomofo` | 日文假名 / 注音符号 / 竖排标点（U+FE3D–FE44）乱码 |
| `box_drawing` | 制表符号与 U+FFFD 替换符 |
| `bare_pua` | `{...}` 之外的私用区字符 |
| `zero_width` | 零宽空格等不可见字符 |
| `unmatched_punct` | 配对符号左右数量不等：`《》`「」『』【】〔〕（）“”‘’〖〗 |
| `trailing_punct` | 题名末尾带句读（`。，、；：？！`）；元曲题名夹着正文（带 `・`）的不查 |

## 口径

**标题与作者名里的空格一律是一个半角空格**（issue #258）。全角空格、制表符、不间断空格等
「非半角空格」都算错（`fw_space`），连着两个以上的半角空格也算错（`multi_space`），
不论夹在哪两个字之间、原来是两个还是更多。空格不是字，底本用两空格分栏（「题  其一」）
也不留：查出来就改，所以这两项没有基线。

**配对符号不逐条要求左右数量相等。** 元曲题名常把曲牌部分截断（「·仙吕)【点绛唇」），
《全唐诗》补逸卷的长题本身就被截断或与下一条粘连，统计上分不清是底本残缺还是抄漏，
所以基线里留着这些，逐条人工判断。可以逐条确认的是孤立右括号这一类，
见 [标题勘误](标题勘误.md)。

## 基线

`scripts/title_baseline.json` 记的是「暂时不动」的数量：

```json
{ "trailing_punct": 2417, "unmatched_punct": 27 }
```

`multi_space` 与 `fw_space` 不记基线：它们是「查出来就该改」的硬错，2026-11 已清空
（97327 处两空格 + 1348 个题名的全角空格／制表符 + 作者名 4 条），留着基线就成了不修的借口。
作者名只剩 `光\t威\t裒` 一处：那是《全唐詩》里三个人合署，换成半角空格会被读成一个人，
`scripts/fix_spaces.py` 的 KEEP 里单独记着，`check_title.py` 照旧报出来。
`trailing_punct` 主要是《全宋诗》
乐府郊祀一类「降神用《高安》。」的旧标点（1042 处）与元曲题名里的正文片段（151 处，带 `・` 的不查）；
`unmatched_punct` 是交代不清的截断长题。两者都要等有本子可校时再动，逐条判据见
[标题勘误](标题勘误.md)。

这两个数 2026-11 重算过：批次 6 把 `rank/` 纳入检查后，排行榜里同一份题名让数字涨了一倍
（1203 → 2420、7 → 29），而 CI 只比本 PR 碰过的文件，`develop` 上没人重算，基线就一直停在旧值。
新基线是改动后的实数，判据没变，见 [标题勘误](标题勘误.md) 批次 8 的「基线」一节。
基线由人工维护（不像 `scripts/check_baseline.json` 那样交给 CI 重算），
因为这里记的是**判定为不改**的数量，数量变少说明有人又清了一批，是好事。
