# 宋词三百首勘正

把 repo 内底本 [`reference/宋詞三百首`](../reference/宋詞三百首) 的 **312 首**与 `宋/宋词/` 的正文逐首配起来，
逐条记下「底本 ↔ 库内」的差别。逐条结果在 [`宋词三百首勘正.tsv`](宋词三百首勘正.tsv)。

这张表是新一轮修《宋词三百首》的依据：先有表，再分批开工（标题与作者 / 正文勘误 / 缺篇补录）。

## 底本

`reference/宋詞三百首`，朱祖謀（彊村）編，民国十三年朱祖母集解本。312 首，
格式是 `### <词牌>[·题注] / <作者>` 加两阕正文，末尾一行 `〔全文完〕`。

`anthologies/songci300.json` 是从同一部书（识典古籍 `7374122395470135333`）抽的目次，
只有 **284** 条，比底本少 28 首；`first_line` 也只留了首句 12 字，题注一律没带。
所以这一轮不用目次，直接用 repo 内的 312 首全文当底本 —— 正文和题注都在，不用联网。

## 怎么配

1. 底本按 `### ` 切块，标题栏再按 ` / ` 切成「词牌·题注」与「作者」。
2. 简繁统一（OpenCC t2s）后去掉全部标点空白，得到纯字串。
3. 库内 21 946 条宋词逐条比对：字数差在 30% 以内、最长公共片段 ≥ 8 字、`difflib` 相似度 ≥ 0.6，
   取相似度最高的那条。312 首里 301 首能这样配上，其余 11 首人工用首句和各句 4 字探针逐首核实过（见下）。
4. 配上之后逐字对：`difflib` 的 opcodes 直接写成「底本「X」／库「Y」」，一处一句。
5. 判定按三类分开记（见下），**这一步全是人工看，脚本只负责把差异摆出来**。

> 与 [`宋词三百首对勘.md`](宋词三百首对勘.md) 的区别：那份是拿 `anthologies/songci300.json` 的 284 条目次
> 去配 `ci.song.*`，只看正文，配不上 121 首；这份用 312 首全文，**配上了 301 首**，
> 并且把标题、作者、正文三件事分开判定。两份表的结论不通用，以这份为准。

### 改题 108 条，其实只有两件事

**一是底本的题注。** 底本 `木蘭花·……` 这种「调名·题注」的写法，库内 `rhythmic` 一律只存调名
（题注在部分记录的 `title` 里）。90 条属于这种，比如苏轼《水調歌頭·丙辰中秋，歡飲達旦…》、
辛弃疾《摸魚兒·淳熙己亥，自湖北漕移湖南…》——**题注不该往 `rhythmic` 里塞**，
但可以按 `title` 的现有写法补上（库内已有 1040 条这么写）。

**二是调名的不同叫法。** 剩下 17 条是真分歧：

## 底本本身的两处毛病

- **目次 108、188 的标题栏混进了词牌注释**：`漁家傲(漁家傲，詞牌名。因晏殊《珠玉詞》…雙調，六十二字…)`，
  是识典古籍页面把注释并进标题了。表里这两条的「底本标题」照抄原样，判定不受影响（正文配得上）。
- 全书最后一行是 `〔全文完〕`，切块时丢掉。

## tag 与这张表对不上

库内挂 `宋词三百首` tag 的有 227 条，这张表配上的 301 条里只有 174 条挂着 tag，另 53 条挂着 tag
却在表里找不到对应目次（多为「同一首的另一读」）。tag 是早年爬取时随手打的，跟底本目次没对过。
PR C 已按底本补挂 88 条，那 53 条**保留不动**（超出的篇目按用户的意思继续保留）。

## 复现

配库这一步没有固化成脚本（选本只有一部、一次性的活儿），口径是：简繁统一 → 去标点 →
字数差 ≤ 30% + 最长公共片段 ≥ 8 字 + `difflib` 相似度 ≥ 0.6 取最高。
其中 301 条自动配上、11 条人工探针核实，全部 312 条逐字看过。

## 2026-11 第二批：归属与缺篇（PR C）

上表出来之后分三批落地：PR A（篇目与作者，见 [`宋词三百首篇目.md`](宋词三百首篇目.md)）、
PR B（正文待核）、PR C（缺篇补录）。这一节记 PR C，做的是**归属与缺篇**，正文与篇目都不碰。

### 补挂 tag 88 条

底本 312 首逐首配库，配上的 301 首里有一批同文记录没挂 `宋词三百首` tag（当年爬取时随手打的，
从没跟底本目次对过）。这次按底本补挂，挂 tag 的记录 227 → **326**，
底本 312 首**每首都有记录挂着 tag 了**（逐首复核过，0 处不合）。

同一首常有两批各收一份（`ci.song.0.json` 简体一批、`ci.song.22000.json` 繁体一批），
补挂时取**已经挂 tag 的那条**为落点，不把 tag 摊到两批都挂 —— 同一首两条都挂，
选本对齐会判成 `multi`。
