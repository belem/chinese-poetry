# 隋的问题：`？年` 被当成了年份

2026-10 把顶层改成 14 个朝代目录时，`隋/诗/poet.sui.json` 收了 475 条，其中 457 条署名「无名氏」。
逐条看下来，真正的隋诗只有 18 首。逐条去向见 [`隋拆分.tsv`](隋拆分.tsv)。

## 根因

`scripts/split_dynasty.py` 按作者朝代决定归属，朝代来自 `authors/authors.json`。
`无名氏` 在作者表里有 13 行，出生年是 `？年`、`?`、`未知年`。原来的写法是

```python
dyn = {a['name']: a['dynasty'] for a in authors}   # 后写的覆盖先写的
```

两个错叠在一起：

1. **同名多行取最后一行**。`dict` 推导式的后写覆盖前写，`无名氏` 于是落到了表里最后一行的朝代上。
2. **`？年` 当数字比**。判朝代时把出生年解析成整数，`？？` 解析不出就退化成「落在任何区间」，隋的
   581—619 区间于是对所有无名氏都成立。

结果：《诗经》298 首、古诗十九首 17 首、经史子集 115 首、乐府民歌 29 首、网传伪托 7 首，全部漏进了隋。

## 修法

`split_dynasty.py` 改了两处：

- `dynasty_index()` 先按作者名分组，一个作者记了几个不同朝代的，判「朝代不明」——这是缺数据，不是
  「归属异说」，不该替学界做一个随机选择。作者表里查不到的，退回记录自带的 `dynasty` 字段。
- 新增 `year_of()`：`？年` / `?` / `未知年` 一律返回 `None`，不参与比较。
