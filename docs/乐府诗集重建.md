## 为什么一卷一档

这部书的编次本身就是内容：十二大类（郊廟歌辭、燕射歌辭、鼓吹曲辭、横吹曲辭、相和歌辭、
清商曲辭、舞曲歌辭、琴曲歌辭、雜曲歌辭、近代曲辭、雜歌謠辭、新樂府辭）各有卷次，
每一大类下按「母题 → 各家拟作」排。原来那两个「卷一汉魏乐府」「卷二南朝乐府」的文件名
是按朝代硬分的，郭茂倩并不这么编，同在南朝的作品也分在相和、清商几大类里。
改成一卷一档之后，`卷N.json` 的 N 就是原书卷次，文件名字典序即篇目次序，
`loader/datas.json` 的 `乐府诗集` 一项按目录读取，不必再另存一份目次。

## 字段

沿用 `docs/目录结构.md` 的记录契约：

```
author    作者，繁体，照底本；底本未署的写「佚名」
dynasty   按作者查 authors/authors.json；查不到的留空（不猜）
title     篇题；篇题下的「同前」还原成母题，「N首」不进题名
category  十二大类之一
subcategory 小类（母题名，如「漢郊祀歌」「巫山高」）
notes     题下注：「一曰…」「某書樂志曰…」这类，不是正文
paragraphs 正文
id        「作者 + 题名 + 正文 + 分段」哈希，规则同 scripts/backfill_ids.py
```

## 2026-11 第二批：底本补全

第一批只抓了目录树的第一层（103 章），卷五十八以后不少卷只拿到「琴曲歌辭 / 思歸引」
这样一两条 —— 因为识典的目录是**嵌套**的，真正的内容挂在 `subChapters` 里，卷五十八下面
其实有 43 个 `<h4>` 篇题。按完整目录树（1309 个节点、1122 个有正文的章节）重抓之后：

| | 第一批 | 第二批 |
| --- | --- | --- |
| 条 | 1851 | 3865 |
| 正文 | 18.8 万 | 35.7 万 |
| 篇题 | 1731 | 2880 |
| 佚名 | 325 | 895 |

同时修掉三类结构错误：

- **level 2 节点重复出内容**：卷七十九〈近代曲辭〉既有自己的章节、又在子节点里再排一遍，
  「紀遼東」于是出现两次。level 2 带子节点时只取它自己那个 `<h3>` 到第一个 `<h4>` 之间（类目序论）。
- **页尾连排下一卷**：卷三十二的章节页末尾接着卷三十一的下一卷，见到「樂府詩集卷第N」即切断。
- **题下注漏收**：以篇题起头的解说（「紀遼東，隋煬帝所作也。通典曰：…」）此前被当成正文；
  小类总注挡在作者行前面时（「南齊書樂志曰：… / 謝超宗 / 正文」）作者也会被吞掉。两处都已修。

## 底本自身的三个坑

**渲染正文与 `paragraphList` 是两份字形。** 识典的章节页把正文渲染成 `<article>` 里的
`<p>`/`<h3>`〜`<h6>`，同时另有一份 `paragraphList` 的行级数据。渲染层把底本的异体字
（朙→明、𦶎→華、髙→高、竝→并、畱→留、㳂→沿）归一到通行繁体，与库内其余书的用字口径一致；
`paragraphList` 保留底本原字形。所以正文与结构都取渲染层，`paragraphList` 只用来核字。

**有些卷被渲染成一大段。** 卷三十七（瑟调曲）、卷五十二以后的部分舞曲卷，页面上十几个篇题
挤在同一个 `<p>` 里，没有 `<h5>`。这类卷按「小类即篇题」处理：一个小类一条记录，
篇题与作者从段首切出。

**篇题尾巴上粘着作者。** 如「晉正德大豫舞歌荀勖」，作者紧贴在题后、其下直接是分首，
没有单独的作者行。生成脚本按「题尾 1—4 字、且它前面那截是同小类出现过的题名」拆出作者；
拆不出的照原样留在题名里，不猜。

## 还没做的

- 正文只与底本一份对勘，**没有与《乐府诗集》别的刻本（四库本、明抄本）逐句校对**。
  异体、异读一律照底本，不据通行选本改。
- 卷八《漢安世房中歌》十七首、卷十五以后的部分乐章，底本本身以「章」为单位连排，
  本篇按底本的分段记录，未强行拆成一章一条。
- 卷八十九等谣辞卷，底本多数篇目不署作者，`author` 记「佚名」。
