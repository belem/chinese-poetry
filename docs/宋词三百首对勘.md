# 宋词三百首对勘

把 `anthologies/songci300.json` 的 284 条目次与 `宋/宋词/` 的正文逐首对起来，逐字看差异。
底本：《宋詞三百首》朱祖謀編，民國十三年朱祖母集解本（识典古籍 `7374122395470135333`）。

逐条结果在 [`宋词三百首对勘.tsv`](宋词三百首对勘.tsv)：目次号、作者、词牌、底本首句、库位置、库首句、结论。

## 怎么对

`check_anthology.py` 按「首句前 12 字」检索，底本行款一乱就整条对不上，284 条里只能命中 83 条。
这次改走两条路：

- **抓底本正文**：章节页 HTML 里内嵌着一整本书的正文数据（`paragraphList`，每段是带 `lineType` 的 JSON，
  `8`=作者、`9`=词牌、`1`=正文）。一次抓全 284 章，不必逐句search。
- **配现库**：正文取 6 字片段建倒排索引，命中后再用 `difflib` 比正文相似度，`>= 0.9` 视为同一首。

结果：284 首里 156 首与库内记录正文高度一致（13 首一字不差），7 首部分一致（多为节选或分阕不同），
121 首在库里根本找不到对应记录。

> 2026-11-02 订正：`宋词三百首对勘.tsv` 的实际分布是 284 条里 `异文不改` 142、`对不上库` 128、
> 空结论 13、`已改` 1。上句的 121 / 156 / 13 与这张表对不上（「154 / 121 / 其它」才是这张表能读出的分法）。
> 这里只标出数字不一致，逐条判定未复核，等下一轮按 tsv 重算后再改。

## 复现

```bash
pip install opencc-python-reimplemented
(cd scripts/shidian && npm install && npx playwright install chromium)

# 1. 抓底本：284 章，逐章 2 秒
W=/tmp/songci300 && mkdir -p $W
node scripts/shidian/chapter.mjs 7374122395470135333 $W/html --catalog anthologies/songci300.json

# 2. 解析出正文（每章 [[lineType, content], ...]，8=作者 9=题名 1=正文）
python3 scripts/parse_chapter.py $W/html --json $W/source.json
```

抓底本走的是章节页 HTML 里的 `paragraphList`，不必逐句检索——一本 284 首的词选逐句搜索要几千次请求，
按 3 秒间隔得几小时，而整本抓只要十分钟。页面渲染报「数据异常」时内嵌数据仍可解析，所以判定成功看 HTML。

配现库、逐字比较的两步没有固化成脚本：选本只有两部，一次性的活儿写死流程比维护一个通用脚本划算。
判定规则见 `docs/宋词对勘.md`（≥2 种古籍支持、且本库读法在任何古籍里都找不到才改）。
